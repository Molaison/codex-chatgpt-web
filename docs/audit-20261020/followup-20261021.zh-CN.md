# 现有问题的第二轮修复

## 范围与完成条件

本轮继续处理 MOL-40、MOL-187、MOL-239、MOL-240、MOL-241 的已记录缺口。起点为上游 PR #18 的 b20cf684 和下游 PR #9 的 7f305763。远端没有新增代码或评审反馈。本地对应代码树为 c2fbdb0 与 013c1b8，工作树均干净。

本轮的可验证完成条件如下。

- 子代理 smoke 在任何模型请求转发前拒绝未批准的模型、Pro、别名及未知映射。允许的非 Pro 路径通过同一入口正常转发。
- `papers/*` 在本地附件存在时核验内容，并把已知摘要带到最终 chat 请求。没有本地附件的已登记论文仍能使用原远端会话。
- 上游在 resolve 和直接 chat 两个入口检查已有 PDF 身份。不同内容、无法核实的旧记录及错误声明在上游调用前拒绝。相同 PDF 只发送问题文本。
- 论文流收到明确终态就释放本轮所有权并结束下游流。开放连接、挂起或失败的 cancel 以及终态之后的数据不能改变已确定的结果。
- 每项都有修复前复现、修复后行为验证和非作者复审。整合后完成相关回归、类型检查及远端 CI。

真实 Pro 子任务 DOM 样本仍缺失。真实 ChatGPT Send、模型请求、PDF 上传及 Zotero 写入均不在本轮执行范围内。真实接口、指定项目、跨设备与崩溃耐久性的验收结论继续区分于受控测试。

## 工作流程

1. Phase A: Frame。读取当前 Linear 和 PR，固定版本与完成条件。
2. Phase B: Design the workflow。按 smoke guard、下游附件、上游身份、流终态分配独立文件与工作树。
3. Phase C: Run the loop。先用生产入口复现，再实施最小修复并验证可观察行为。
4. Phase D: Keep the audit trail。将证据和取舍追加到本目录的 decisions.tsv，保留失败结果。
5. Phase E: Verify and hand back。交叉复审、整合测试与最终 CI 后更新现有 PR 和 Linear。

## 设计取舍

过滤模型目录只能减少误选，不能阻止直接请求或回退。smoke 需要在实际请求边界验证允许的公开模型及解析结果，产品正常模型目录不受这项测试约束影响。

每次强制读取 PDF 会破坏没有本地附件的跨设备续聊。下游只在附件存在且有本地路径时核验内容。已知摘要同时参与 resolve 与 chat，避免把一次查找当成以后所有请求的内容保证。

既有 ready 记录如果既无存储摘要，也无 SHA256 形式的规范身份，就无法证明当前附件与旧远端 PDF 相同。新客户端的声明不能补造历史证据。这类记录仍可进行无附件的文本续聊，但带附件或摘要的请求明确报告无法核验。

## 修复前证据与实施

### 调用前模型限制：MOL-187

原 `smoke-codex-web-subagents.ts` 暴露完整模型目录，直接把请求交给 bridge，仅依赖提示词限制 fallback，并在运行结束后检查 rollout。受控的 fake Codex 可执行文件向原脚本提交 Pro 请求后，本地模拟上游被调用 1 次；要求调用次数为 0 的回归失败。这是调用前约束缺失的直接证据，不是真实 Pro 调用。

本轮在 smoke 自己的 loopback 入口验证实际请求，复用生产 parser、模型路由及配置，固定公开 slug `chatgpt-web/gpt-5.6-sol` 和 medium/high，拒绝 Pro、别名、native、缺省及未知映射。目录只保留同一已批准模型。每次请求重读配置，端点变化、模型不可用或重定向会拒绝；首次 policy failure 后停止后续转发。HTTP 503 可以原样交给客户端，不把它误判为换模型。

独立复审还发现原 smoke 可在 child 缺少完成记录、wait 输出未关联真实 child/call_id 时误报成功。验收据实际 V1 协议收紧父子身份、完成 marker/version 和 targeted wait 的终态关联。此项是现有 smoke 的限制与验收修复，仍不等于真实 Pro 子任务 DOM 能力适配。

### 上下游 PDF 身份：MOL-241、MOL-40

下游新增 12 项身份测试在修复前为 3 pass / 9 fail。修复后 `papers/*` 的 ready 路径会读取可用本地附件、核验 `%PDF-` 文件头及内容摘要，重新 resolve，并把已知 hash 传到最终 chat。无附件或无本地路径仍可续聊；实际读取失败、非 PDF、取消和核验期间 thread/state 改变不会被当作无附件。

上游原本在 ready chat 中移除附件而不检查内容。实际 pool 回归在修复前得到 HTTP 200，而期望为 409。现已在移除附件之前核验声明、实际字节与已存摘要；同一 PDF 校验后只转发文本，不同内容及不可信旧 hash 在上游调用前拒绝。新 hash 声明不能填补旧 DOI 记录未知的历史内容。

上下游联合复审使用实际 `prepareCprPaperRequest → createQaPool.fetch → registry/SQLite/conversation store`，只在最终后端返回受控完成响应。13 项场景通过，9 次受控后端聊天仅有 1 次初始 PDF 内容。覆盖独立 Prefs 实例模拟的新设备、附件替换、显式附件、无附件、hash alias、新 DOI、直接 chat、legacy 缺摘要及 pool 重启。

### 首个终态结束论文请求：MOL-239、MOL-240

原 pool 仍等待 EOF 或 await 上游 cancel，使已经完成或明确未发送的论文继续占用会话。16 项新增回归在修复前为 1 pass / 15 fail。修复后首个有效 completed、failed、incomplete 或 error 决定本轮结束；release 幂等，cancel 挂起或拒绝不阻塞下游收尾，终态后的冲突或坏数据不改变结果。

completed 仍须验证响应形状和已保存的 conversation 映射后才能晋升 ready。明确发送前失败保留原 reservation 的安全重试；其他失败继续 uncertain。非 paper receipt 的持久化和回放语义保持原有路径。

独立复审额外验证了每个字节切分点、缺映射/缺 ID、取消与已入队 completed 竞争，以及旧 cancel 延迟拒绝不能清除下一轮 owner。旧测试期望首个 failed 后的坏 JSON 继续制造传输错误，与新终态契约冲突，已改为断言 failed 被交付且坏尾帧不外泄。
