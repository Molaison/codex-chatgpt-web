# 6.1.26 session synchronization

Persistent conversations now checkpoint instructions together with accepted
history. When the system, developer, tool and transport instructions are unchanged,
subsequent submissions include only the new context and the current turn token.
Changed instructions, legacy checkpoints without a fingerprint, forks, compaction
and recovery still require a complete instruction refresh.

The Full daemon prefers its packaged sibling browser helper. Capability
negotiation preserves compatibility with older Launcher helpers, and continuations
without the required callback remain rejected.

Completed browser turns now recognize localized error panels, semantic retry
controls and errors from a response stream owned by the current turn. User
quotations, tool output, approval prompts and active generation do not qualify as
terminal errors. Incomplete turns retain their execution and tool receipts;
detecting an error does not replay the submission.

An owned input-size rejection invalidates its instruction checkpoint, including
rejections delivered inside an HTTP 200 response stream. The
conversation mapping, accepted history and tool receipts remain intact, and an
older owner cannot invalidate a newer checkpoint.

Instant completion uses a 150 ms stability window and 50 ms idle polling, while
preserving active stream and tool completion fences. Composer reuse and routine
diagnostics reduce preparation overhead. Native browser target identity and
viewport invalidation checks remain in place across navigation, resize and
renderer replacement.

This snapshot also preserves the existing model identity, session, paper recovery
and Launcher fixes from the deployed 6.1.26 baseline.

## Validation and limits

Type checking and focused regressions passed for instruction checkpoints, helper
compatibility, response completion, terminal errors and browser ownership. Four
failures in the initial 304-test run were corrected; all 160 affected tests passed
on the final source, and the other 144 passing cases were unaffected. Terminal
error and terminal contract checks passed separately.

On one live account, three same-thread Instant tool turns each executed one real
read-only shell command and completed in native Codex. An independent chat request
also completed. Delivery from the helper's confirmed terminal timestamp to the
native final event took 49, 47 and 54 ms. These measurements exclude generation
and the native CLI's process shutdown.

The three browser submissions contained 6485, 8814 and 844 characters. The second
submission correctly refreshed instructions after native developer instructions
changed; the third used the incremental contract without repeated instructions.

For the reported steering incident, the successor operation started 687 ms after
steering. The 23.920 s interval to send acceptance included preparation and
acceptance observation, so it is not evidence of waiting for the preceding turn
to finish normally. No scheduling change or additional forced cancellation was
introduced.

The original browser alert text was not retained. Its specific upstream cause
cannot be reconstructed, and the successful canaries do not establish that the
original unknown failure was reproduced.
